# 运行与归档

在首次配置、启动解析、恢复任务或迁移既有产物时读。命令入口为安装目录内的 `scripts/analyze.py`；不要为了运行而把媒体或凭据复制到版本化 skill 源码里。

## 本机配置

`configure` 接收 `--account-file`、`--ffmpeg`、`--ffprobe`，可选 `--locale`。配置保存为安装目录内的 `config.local.json`，不进入版本控制。

- `account_file` 指向用户提供的账号文件，保存的是路径，不是账号内容；文件过期或不存在时请用户提供新的来源，不搜索其他账号。
- FFmpeg 与 FFprobe 必须实际能运行；先复用已有安装。Python 使用 3.10+，脚本主流程仅依赖标准库；已有 Pillow 时额外生成接触表，缺少时可逐张核对真实抽样图，不因此安装依赖。
- HTTPS 保持证书与主机名验证，并沿用 `SSL_CERT_FILE` 或系统已有的可信根。若 Python 的 CA 库为空，客户端只复用本机已安装的 `certifi` 证书包；没有可用证书包时，在读取账号内容和发送登录前返回 `local_ca_bundle_required`，应先配置可信的 CA 文件，不关闭验证或自动安装软件。握手证书校验失败返回 `tls_certificate_verification_failed`，与提交后结果不明的网络错误分开记录，均不自动重发。
- 认证服务目前支持 macOS arm64 与 Windows x64；其他平台仍可使用离线归档和报告操作，不能伪装平台登录。
- 默认服务为固定的 AIGV HTTPS 认证、S7 Whisper `large-v3` 与 `gpt-6.1-sol` Responses 路由。若协议或模型已变，以实际所属源码核对，不把任意兼容地址当作可信认证目的地。
- 日常解析授权包含正常登录和既定服务调用；不能据此替用户更改密码、扩大权限、选择新的付费服务或公开文件。

## 命令职责

所有命令均以 `python3 <安装目录>/scripts/analyze.py` 开头。全局 `--output-root PATH` 只用于用户明确覆盖或隔离验证，应放在子命令之前。

| 子命令与输入 | 行为 |
| --- | --- |
| `configure --account-file PATH --ffmpeg PATH --ffprobe PATH` | 保存本机路径；`--locale zh-CN` 可指定报告语言 |
| `inspect VIDEO` | 只读探测文件与流信息，不登录、不调用模型 |
| `prepare VIDEO` | 建立新运行目录、探测视频并抽帧，不登录；可用 `--frames N` 指定本次采样预算 |
| `run VIDEO` | 新运行：准备媒体、登录、完整转写、图文分析、渲染、验证、退出；可用 `--frames N` |
| `frames RUN_DIR --at 10,20,30` | 在指定源时间补充真实抽样图，不调用模型；总数不超过单次图像预算 |
| `resume RUN_DIR` | 复用已完成阶段继续；`--notes FILE` 带入已核对的视觉观察或不确定项 |
| `cleanup RUN_DIR` | 对本次运行保留的私有会话重试退出；不登录、不转写、不推理 |
| `render RUN_DIR` | 根据已保存分析离线重建报告，不调用认证或推理接口 |
| `import-existing OLD_DIR` | 将已有完整产物复制进固定归档，修正局部资源路径并登记目录；不删除或修改旧产物 |
| `index` | 重建归档总入口，不重新分析视频 |

开始推理前，应先审阅抽样画面。对图表、软件界面或演示密集的视频，优先使用 `prepare`，检查实际图片后把观察记录交给 `resume`；无需仅为检查画面重新提交整条推理请求。

## 固定目录结构

默认根为 `<安装目录>/outputs/`。视频目录形如 `<视频名>--<源摘要前12位>/`，其下每个 `<运行时间>--<随机标识>/` 是不可覆盖的历史运行。

| 产物 | 用途 |
| --- | --- |
| 根目录 `index.html`、`index.json` | 全部视频、运行版本、状态及报告入口 |
| `report.html` | 自包含报告，顶部“整片洞见”，图像可随报告携带 |
| `metadata.json`、`run.json` | 原视频身份、时长、执行路径、阶段与状态 |
| `transcript.txt`、`transcript.json`、`transcript.srt` | 带源时间的原始 ASR 转写及时间质量信息 |
| `frames/`、`frames.json` | 实际抽样图及源视频时间；目录内优先使用相对路径 |
| `analysis.json` | 可编辑的报告内容与推断依据 |
| `evidence/` | 原始转写响应、模型响应、事件及调用状态记录 |
| `verification.json` | 实际执行的检查、跳过项与已知限制 |

音频中间文件与认证会话放私有临时目录，不进入报告归档。会话目录权限为 `0700`，含令牌文件为 `0600`；结束时尝试撤销会话。撤销结果未知或部分失败时如实记录，不宣称已退出，也不丢失仍需处理的私有状态。

## 恢复与失败

- 根据源摘要、请求摘要与阶段完成记录复用成果；同名文件被替换后，不沿用旧转写或旧时间码。
- 已完成的转写和模型结果先读取再继续，不能凭任务标题决定重发。
- `in_flight`、`outcome_unknown` 或没有明确完成事件的推理状态，都需要先核对结果；`resume` 不意味着允许重放这些请求。
- 已知输出上限截断可保存已完成字段，再提交明确缺失范围的补充任务；补充请求也保留独立响应与状态。原始截断响应不能被覆盖成成功。
- 媒体、转写或上下文超过实际限制时，按语义和时间分段，记录来源区间与合并依据；缺失的部分在报告中明确标出。
- 未授权的网络安装、服务迁移或账号恢复不属于普通解析步骤。存在具体阻塞时报告已完成阶段和继续所需条件。
