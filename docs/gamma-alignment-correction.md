# Gamma 旧录屏画面与解说对齐修复

2026-11-04，Codex 根据用户反馈修复。用户对24秒 Gamma 复用片指出“感觉画面和字幕没有关系”；该片现按拒收处理。原片、原生工程、历史技术报告和既有上传不改写。没有把技术解码通过当作内容验收通过。

## 已确认原因

旧计划把24秒机械分为三个8秒片段。第一句仅介绍虚构演示；第二句“逐页预览，检查画面与字幕是否对应”、第三句“最后核对剪辑链路，并保留实际检查结果”是制作流程检查语，无法解释实际出现的工作法和学生示例。第二个区间还横跨封面、过渡和不同页面，单句并未绑定稳定可见内容。TTS未超字幕时间、总帧数正确，并不能解决这些语义问题。

源录屏只能支持已有虚构演示的页面预览；不能凭这些画面声称 Gamma 生成、编辑功能、PPTX导出、价格或处理速度已验证。无需为凑24秒补写功能或把画面冻结后伪装成实操。

## 方案来源与局部修复

按用户偏好实际调用现有 Claude Code 的已授权供应商，safe-mode、空工具/空MCP、无hook、无会话持久化。该单次调用55秒超时、零stdout/零stderr、实际进程退出143；没有可用草稿或可确认的响应模型。本次局部校验设计、review与实施由 Codex 完成，不冒称 Claude 产物，没有反复重启长调用。

新计划使用每句 visual_alignment：实际可见内容、准确clip和源帧区间。校验器拒绝跨所指片段、映射不一致或缺句。没有映射的旧协议仍可准备，但不会获得新的语义验收通过。

新增 review CLI 记录准确 plan/export 哈希及逐句观察、时间、文字和证据。只有每句都审查且证据未变才可能批准；明确拒收在同一日志中对相同成片字节保持有效，不能用旧批准、改计划格式或伪报角色清除。收据是有归因的人工/操作员观察，不是自动语义理解或独立身份认证。没有自动发布授权。

旧片用户拒收已追加为rejected，未重写旧verification或旧媒体。对旧片任何再次验收应先读取拒收日志；未来跨attempt的引用仍需统筹保留。

在原30fps导入派生片中检查实际页面变化，先提取候选首/中/末帧。初选学生示例到源帧591时，末帧590已进入“三步工作法”；因此缩短该源区间到570，不把错误末帧宣布通过。原抽帧证据保留。
