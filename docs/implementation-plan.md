# 实施计划

版本：v0.2（review 修订稿）· 2026-11-02 · 配套：[架构](technical-design.md)、[数据与状态](data-and-state-contracts.md)、[验收](validation-plan.md)、[review](review-report.md)。doc2/doc4 分别指数据与状态/验收文档。

**状态声明**：以下全部为**计划**。当前仓库没有产品代码；任何里程碑的"完成"以 `docs/validation-plan.md` 的验收项通过为准。
**估时**：仅标"人日"级粗估，且基于 `[假设]`——1 名熟悉 Python 与 FFmpeg 的工程师、桌面环境已可用、无外部阻塞。**不是承诺，也未与团队校准。**

## 1. 拆分原则

1. **先做不可逆的骨架**：状态、租约、产物提交三件事一旦做错，后面全是补丁。
2. **每个工单有独立可验产物**：能不看别的工单就判断"完成没完成"。
3. **先打通一条最窄的真实链路**，再补质量与对账；不在没有真实样片时做平台适配。
4. **Agent 相关工单必须能在真实 Codex 运行时验证**，不能用假 Agent 代替（`[待验]` 项见 §7）。

### 1.1 先做纵向样片探针

在完整状态库和调度骨架投入前，先以人工监督的安全流程验证：固定输入 → 真实实测录屏 → 声音与字幕 → 最小剪辑单 → FFmpeg → 人工全片看听。首版默认人工提供具有使用权的旁白文件，TTS 只定义接口和预算/未知结果契约，不作为首条样片的阻塞条件。探针验证媒体链路与账号可用性，不替代 M0–M6 的隔离、恢复、审批验收，也不声称无人值守可用。

## 3. 里程碑

| 里程碑 | 主题 | 完成标志（一句话） | 阻塞关系 |
| --- | --- | --- | --- |
| M0 | 骨架与契约落地 | 迁移脚本、事件表、CLI 空壳、schema 测试通过 | 无 |
| M1 | 单机协调 + 租约 fencing | 杀进程后新执行者接管，旧者所有请求被拒 | M0 |
| M2 | 真实实测与录屏 | 一次真实网页工具测试 + 正式录屏 + 证据入库 | M1、桌面链路 |
| M3 | 文案冻结 + FFmpeg 成片 | 从实测证据生成 60 秒 MP4，可重建 | M2 |
| M4 | 全片 QA 与人工校准 | 全解码 + 覆盖日志 + 人工看听一致 | M3 |
| M5 | 人工交接发布与对账 | 发布包 + 审批 + 外部状态核实 + 不重复提交 | M4 |
| M6 | 恢复与故障注入回归 | doc4 §4 全部场景通过 | M2 起持续 |
| M7+ | 能力扩展（按触发条件） | 见 §6 | 各自触发 |

M0–M6 合计粗估 **35–53 人日**；另有 E1–E5 约 2.5–5 人日、探针与账号等待。可并行部分会改变日历工期，这些数值均未经过团队验证。

### M0 骨架（约 3–5 人日）

输入：本文与 doc2。
产出：`db/migrations/001_init.sql`（全部表 + 触发器）、`avcd` 可启动并接受 `avc status`、`events` 写入、迁移幂等测试。
依赖：无。
验收：清库 → 迁移 → 二次迁移无变化；`PRAGMA foreign_keys` 生效；关键唯一索引可击穿测试（插入第二个 running attempt 被拒）。

### M1 协调与 fencing（约 6–9 人日）

工单：
- W1.1 调度循环（依赖求值、`ready` 判定、退避）——验收：构造 5 节点 DAG，顺序正确。
- W1.2 attempt 生命周期与心跳——验收：心跳过期触发 orphaned。
- W1.3 `desktop_gateway` 会话与 epoch——验收：epoch 落盘重启后不回退。
- W1.4 回收流程（先禁旧授权并持久化递增 epoch→取消/排空网关在途动作→终止并确认进程组→封存→确认 free 后授新任务）——验收：doc4 F1–F4。
- W1.5 产物提交（受控文件描述符复制到协调器私有 staging、哈希复核、对象库原子发布 + DB）——验收：进程崩溃模拟（kill -9；不等于断电耐久性测试）后无悬空引用。
产出：可跑的双执行者抢占实验日志。
依赖：M0。

### M2 实测与录屏（约 8–12 人日，含环境不确定性）

工单：
- W2.1 `web_fetch` 受限工具与来源记录 Skill。
- W2.2 浏览器录制（Playwright 显式 viewport/尺寸，关闭后校验文件）。
- W2.3 OBS 控制（仅 GetRecordStatus/StartRecord/StopRecord，未知则查、不 toggle）。
- W2.4 证据登记（截图/结果文件/视频区间）与 `capture_manifest`。
- W2.5 test_run 记录与"页面提示 ≠ 结果"的检查清单落到 Skill。
验收：一条真实网页工具从登录 → 操作 → 得到可打开的结果文件，全程有证据；录屏可解码且覆盖输入/动作/结果。
风险：`[待验]` 登录与会话稳定性、OBS 与浏览器同屏的帧率与音频。

### M3 文案与成片（约 6–9 人日）

工单：
- W3.1 `claims`/`script_versions` 与冻结守卫（doc2 §7）。
- W3.2 `edit_plan` schema + 校验器（拒绝未 cleared 素材）。
- W3.3 FFmpeg 渲染器：模板 v1（顶部标题、横屏区、字幕、安全区）、确定性参数、报告。
- W3.4 可重建性：固定编码器/字体/参数环境测试字节确定性；跨环境按预先冻结的媒体参数、帧/音频等价容差验收并记录血缘，不承诺相同哈希。
验收：从冻结文案与证据，一条命令产出成片；在测试副本仅删除可重建的渲染输出/缓存，保留原素材对象、edit_plan、字体、模板和版本化工具链后可重建；绝不删除整个 var 或唯一原片。数据库/发布状态采用独立的一致性备份恢复演练。

### M4 全片 QA（约 4–6 人日）

工单：
- W4.1 全解码与媒体参数校验（时长 58–62s、1080×1920、30fps、音轨存在）。
- W4.2 全帧统计（黑帧、冻结帧、静音段、响度）。
- W4.3 字幕对齐与错字检查（基于字幕文件，不替代看听）。
- W4.4 覆盖日志（审看区间记录）与判定规则。
- W4.5 人工校准手册与首批双人看听。
验收：doc4 §5 全部通过；构造 3 个缺陷片（错字、静音、对比不一致），QA 能定位到镜头。

### M5 发布交接与对账（约 4–6 人日）

工单：
- W5.1 发布包生成（封面/标题/简介/标签/声明/素材清单）。
- W5.2 意图 + 去重键 + `awaiting_human`。
- W5.3 `avc approve publish`（独立人类身份与受限审批通道；PTY 不能冒充；绑定完整发布包和目标）。
- W5.4 预写日志 + UNKNOWN + 对账命令。
- W5.5 `human_handoff` 适配器：人工上传后回填 `work_id`。
验收：doc4 §7 的全流程，包括"人工已上传但未回填"的对账。

### M6 恢复与回归（约 4–6 人日，穿插进行）

产出：故障注入测试套（doc4 §4）、恢复手册、`avc recover --dry-run`。
验收：全部注入场景通过且无重复提交、无原片覆盖。

## 4. 关键路径与并行

```
M0 → M1 → M2 → M3 → M4 → M5
              └→ M6 随 M2 起并行
M3 的 W3.2/W3.3 可在 M2 收尾前用样例素材开发（但不得作为验收）
```

- 单人项目：严格顺序。
- 两人：A 负责 coordinator/gateway，B 负责 render/qa；M3 起 B 提前做渲染器。
- 三人：第三人做 Skill 与验收脚本，避免"只有开发者能验收"。

## 5. 首阶段必须完成的"证伪实验"

这些不是功能，是**决策输入**，做完可能改变方案。建议在 M1 之前或并行做（各 0.5–1 天）：

| 实验 | 问题 | 若结果为否 |
| --- | --- | --- |
| E1 | Codex 子 Agent 能否稳定执行自定义命令并继承所需工具？ | 退回"主聊天 + 脚本"形态，Agent 岗位仅作文字角色 |
| E2 | Agent 进程能否做到无桌面能力（独立用户/容器）？ | 停止无人值守桌面执行，转人工监督且单独验收；不得继续声称网关独占或 fencing 生效 |
| E3 | OBS 能录到浏览器画面 + 系统声且音画同步？ | 改用 Playwright 画面 + 单独音轨对齐；或接受无声+配音 |
| E4 | 中文字体在 FFmpeg 下渲染一致？ | 预渲染字幕为透明 PNG 序列（成本上升） |
| E5 | 现有模型对 60 秒全片审看能否发现人为植入的 3 个缺陷？ | 强化确定性检查 + 提高人工比例 |

## 6. 扩展触发条件（不提前引入复杂度）

下表阈值是 `[假设]` 的评估触发线，不是测得的容量拐点；达到后先测量瓶颈，再作选型。

| 能力 | 引入条件（可测） | 触发前不做的理由 |
| --- | --- | --- |
| 多桌面/多机 | 连续 2 周桌面队列 p90 等待 > 30 分钟，且单机日产能 < 需求 | 单机足够；跨机会放大 fencing 复杂度 |
| 外部队列（Redis 等） | 单 job 任务数 > 200 或需跨进程多写者 | SQLite 单写者已够 |
| Postgres | 需要多机共享状态，或 DB > 5GB / 写 QPS > 50 | 迁移成本高 |
| 剪映适配器 | 一条视频通过"导入→编辑→完整导出"全链验收，且能产出可重建依据 | `[待验]` 自动化能力不足 |
| 自动 API 发布 | 平台权限获批 + 完成 doc4 §7 的幂等/对账验收 + 人工抽检通过 | 未验收即自动化风险不可控 |
| 定时自动触发 | 手动跑 10 条样片无人工干预阻塞 | 自动化会放大未发现的恢复缺陷 |
| 多工具合集/长视频 | 模板参数化完成且有 3 条单工具样片 | 结构与素材需求不同 |
| 分布式追踪/指标平台 | 单机日志排查耗时 > 每次 1 小时 | 过度建设 |

`[决定]` 任何扩展都必须先更新 doc2 的契约与 doc4 的验收，再写代码；不允许"先实现再补文档"。

## 7. 风险与待决策

### 7.1 风险

| # | 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- | --- |
| K1 | Codex 运行时无法满足 E1/E2 | 中 | 架构前提失效 | 提前做实验；准备降级方案 |
| K2 | 真实软件登录/验证码频繁 | 高 | 实测阶段反复阻塞 | `needs_input` + 人工介入流程；优先选免登录或可用 API key 的工具 |
| K3 | 录屏音画不同步 | 中 | 成片观感差 | E3 先测；必要时分离录制 |
| K4 | FFmpeg 字幕排版达不到参考片观感 | 中 | 需额外设计工作 | 预渲染字幕层；模板先做静态 |
| K5 | 模型质检不可靠 | 中 | 漏判 | 确定性检查为主，人工校准 |
| K6 | 素材许可判断错误 | 低-中 | 法律/下架 | 许可状态硬门禁 + 条款快照 |
| K7 | 人工交接成为瓶颈 | 高 | 产能受限 | 明确这是首版预期，不是缺陷 |
| K8 | 预算估算失真（模型调用波动） | 中 | 超支 | 准入预留 + `budget_blocked` |

### 7.2 待决策（需人类拍板）

1. **D-1 隔离强度**：是否接受"独立 OS 用户"作为最低要求？若部署环境不允许，阻断相应自动化并改成人工监督，不能通过书面声明绕过隔离门槛。
2. **D-2 音频来源**：首版默认人工提供合规旁白；之后是否引入 TTS，以及供应商、声音权利、价格上限和超时对账能力，需另行确定。
3. **D-3 模板字体**：使用哪款可商用字体（需确认授权），未确定许可前阻断字体使用；预渲染不豁免字体授权。
4. **D-4 首版平台顺序**：先做哪一个平台的人工交接流程（建议先小红书网页端或抖音创作中心，取决于账号现状）。
5. **D-5 素材源**：是否只用自有/官方素材 + Pexels/Pixabay，还是允许更多来源（影响许可审核工作量）。
6. **D-6 预算默认值**：单条视频上限与告警阈值（本文不给具体价格）。
7. **D-7 质检通过标准**：`pass` 是否要求人类签字，还是 Agent 达标即可（建议首 10 条必须人签）。

### 7.3 待验证（`[待验]` 汇总）

见 doc4 §9 与本文 §5；核心是 E1–E5 与平台权限。**在这些完成前，不得对外称"自动发布可用""无人值守生产"。**
